# 假设驱动排障

触发：实际行为偏离预期，原因未知且影响修法。原因已可靠定位则直接修复和复测。

1. 用最短路径描述预期、异常、正常对照、发生条件和影响范围。
2. 沿输入、处理、输出找到最早偏离处。对可信解释写下不同的可观察预测，不机械凑固定数量。
3. 优先选择能区分解释的复现、日志比对或最小试验。结果对所有解释都相同时，换条件；没有证据时不连续猜改。
4. 依据观察修复相关位置，复测异常、正常行为及真正的用户入口。已授权的紧急恢复可先执行，恢复成功不等于根因已确认。

例：重试后重复公告。

| 解释 | 区分观察 |
| --- | --- |
| 上游重复提供输入 | 写入前已出现两条同标识输入 |
| 成功写入后被重投 | 同一投递标识有首次成功和再次写入记录 |

一次受控重投可检验幂等性。修复验收包含：重复投递只产生一条记录，同标题不同标识的公告仍分别保存，正常展示可用。只剩截图、无日志和复现环境时，交付现象、候选解释和最小所需观察，根因保持待证。

停止：有足够证据支持处置且复测通过，剩余原因不会改变行动；否则注明受阻观察与影响。

## 条件辅助：系统因果图

只在跨组件反复故障、普通排障无法解释复发、关系会改变行动时使用。

选择少数相关变量与时间段。例：超时增加 → 重试增加 → 队列积压 → 响应变慢 → 超时增加。每条箭头分别附对应日志/时间序列；仅仅先后发生不足以确认因果，缺依据的箭头标为假设，并标明延迟。

选一条最能区分解释的联系检查，例如在隔离环境限制重试后观察积压与超时。发现可指导修复或监控的联系即停止；继续画图只增加推测时结束。无需绘图工具，短关系列表足够。
