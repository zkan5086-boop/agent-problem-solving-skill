# 方案权衡

触发：至少两个可行方案在效果、体验、成本、工期、维护或可逆性上存在影响目标的取舍。已有做法可靠、易恢复且足够时直接沿用。

1. 说明决定和硬约束，复用用户已定目标、优先级与预算。排除违反约束的选项；维持现状可行动时纳入比较。
2. 用相同且与目标有关的标准比较可行路线。估计写出范围和依据，不制造精确分数或无依据的成本数字。
3. 找出会翻转推荐的前提。可廉价验证就做最小试验；只剩用户拥有的产品取舍才提问。
4. 给推荐、主要代价、改选条件。已授权实现则接着实施；仅请求建议则止于建议。

例：增加公告来源总要多处改动。先追踪真实来源和变动记录，确认是接口耦合还是配置重复。比较维持现状、小范围统一接口、全面重构；按需考虑旧数据兼容与迁移风险。若只是配置重复，选择配置整理。不要因为用户说“架构”就推荐重构。

停止：推荐满足硬约束，合理的剩余变化难以翻转；关键未知暂不可测时给条件式推荐和影响。

## 共用动作：最小试验

此动作供三个方法复用，不是第四套必走流程。

记录：假设｜有区分力的检查与通过条件｜代表样本/环境/成本和权限边界｜实际观察｜行动。

例：统一解析接口能覆盖已有两类公告。先选两类代表样本，在隔离环境验证日期、标识和正文转换，检查旧来源输出与旧记录兼容。写清哪些失败会否决统一接口。试验成功只支持这些样本和环境，不证明所有来源可迁移。

产品例：让真实参与者从原型找到下一道复习题，记录是否无需指导完成。AI 角色模拟只能检查流程假设，不能声称学生已验证可用或长期学习效果提高。

一轮足以决定下一步就结束。追加试验必须有观察产生的新疑问，并说明结果将怎样改变行动。
